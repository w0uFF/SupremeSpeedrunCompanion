# Timing — independent offline interval (P0-T16)

Public use cases: elapsed_ns(begin,end), Interval::start/poll/finish/result; Result carries both raw ClockSample values plus integer nanoseconds. Inject a borrowed IClock that outlives the interval. One non-copyable interval per attempt, single owner thread, synchronous sampling, no engine callbacks, no worker, no IGT synthesis. Repeated start/finish rejected; final time remains frozen; invalid frequency, overflow, backwards observed samples or clock exception leave the interval invalid. No automatic retry or wall-clock fallback.

Supported frequency range 1..1,000,000,000 Hz; quotient/remainder integer conversion truncates fractional nanoseconds, checks overflow and retains raw samples. This bound deliberately rejects unsupported timebases rather than overflowing. PlatformClock uses QPC/QPF on Windows and steady_clock nanoseconds on Linux. No claims about actual effective resolution, sleep/resume or timing overhead until measured. No event semantics version is assigned until G2. Pause/reset/restart handling and official IGT are separate concerns. No native capability or schema changes.

Dependencies: contracts/observation.hpp, standard C++17; Windows API only in infrastructure/platform_clock.hpp. No external library or configuration, persistent state or feature dependencies. Isolated target P0_independent_timing; not registered with bootstrap. Disable by leaving unused; remove the module and its CTest target without affecting existing code. See tests/test_timing.cpp: exact conversion, overflow, invalid frequency, clock failure, freeze, regressions, actual local platform clock smoke test. Windows QPC branch requires Windows CI execution; game lifecycle requires human G2.
