## Module boundary and lifecycle
Feature-local public/comparison.hpp defines Subject, Metric, Measurement, Evidence, Observation, Source, Result and Controller. Required read dependency is const run_library::Repository::find; optional Source provides a fresh independently verified archive/member and separately established measurement. Reuse public exporter::exchange Verified/Slot/valid/same, playback::Member/valid_member shape, run_library record validation/identical/key and categories::Track/valid. No dependency on private adapters, history annotations, playback execution or engine. No new parser, hash, database, schema, configuration, threads, queues, persisted state, mutation or startup/shutdown side effects. Caller owns repository/port lifetimes and serializes on trusted quiescent I/O owner outside game/render callbacks. Omit source to disable; unavailable does not affect other modules. No caching, scan, implicit comparison or automatic retry. Exactly two distinct selected runs and one metric per call, at most two index lookups and two source calls. Long hashing inherited from a future adapter is not a frame-safe operation; no hard deadline.

## Selection, evidence and results
Both inputs require complete valid existing nonlocal unclassified projection and exact whole ZIP SHA-256/count; imported and synthetic only. Local/unindexed staging unsupported because current guarded archive identity is nonlocal. No change to existing local-only repository::comparable/best_local semantics, no relabeling of imported runs. History raw sorting is not authoritative comparison. Re-read each exact immutable Record and verified finalized archive; reject absent/pending/alias/review/unavailable or mismatched observations. For media metrics explicitly select exact verified case-sensitive member name, kind, positive length and digest; reuse playback member bounds and require native replay member <=8 MiB (current diagnostic reader bound). Record metrics require no selected member. No path or member auto-choice. Measurement must be independently established by trusted Source on same exact Subject and metric, identify a valid typed track/difficulty and bounded versioned semantic key, and supply actual measurement in that domain. The adapter MUST establish single-attempt boundaries, matching semantics, source/format and any necessary media mapping independently, not echo index claims or trust manifest labels. Source is an injected trust boundary, not a verifier of arbitrary report JSON. No production source implemented. Existing bound track/interval/coverage comparators check consistency of supplied attempt keys, tracks, tick epochs, intervals and coverage; agreement alone cannot establish real observations. Reuse them upstream when evidence exists; do not derive track identity or coverage from sentinel category/profile, same folder or filename. Weather/rider/board not made competition restrictions.

Result returns explicit metric and state. After both exact identities match, recorded_claims for IGT/RTA preserves optional raw index values (including zero), clearly unverified; no raw claim fallback or media-derived claim. No delta unless both subjects have established valid measurements, finished status, equal typed track and semantic key. For record metrics, also require recorded value present, known index event_semantics equal measurement semantics and independent measured value equal recorded value. A disagreement is review, not correction or violation. For media metrics the semantic key independently specifies interval/interpretation, not borrowed from manifest IGT/RTA or arbitrary time conversion. Both media roles must match requested domain. Invalid or unsupported input is refused before I/O; stale selection, missing, unavailable, insufficient evidence, unsupported, incompatible and review_required distinct. Current identity failures short-circuit first then second. After both identity checks, evidence review/malformed precedes stale, unsupported, unavailable, insufficient; incompatible track/semantics checked only with both valid measurements. Exceptions yield unavailable. Only compared carries copied measurement pair and delta; no partial comparison or authority. Even compared is descriptive within trusted adapter scope, not authenticity, official IGT verification, eligibility, ranking, policy evaluation or absence of cheating. No mutable annotation or repository mutation/PB lookup. Same run ID refused; no assumption that distinct IDs imply distinct underlying gameplay. Serialized snapshots are not atomic cross-store transactions, hostile race/ABA or provenance guarantees.

## Metric bounds and arithmetic
- igt_ms: independently corroborated recorded IGT in integer milliseconds; 0..INT64_MAX.
- rta_ns: independently corroborated recorded elapsed RTA in integer nanoseconds; 0..INT64_MAX.
- video_interval_100ns: independently mapped single-attempt interval within selected video, not total clip duration/menu or result tail; provisional 0..(6h+1s) in 100ns units, aligned with B-PLAY-01 bound, not a measured decoder limit or competition rule.
- replay_candidate_ticks: selected candidate start-to-finish interval in raw ticks; 0..65535 from existing uint16 header diagnostic; use existing replay_header/replay_compare for future safe isolated reader. No physical units, ms conversion, official split, checkpoint geometry, speed or actual native playback inferred. Current replay_compare requires external same-track assertion and is diagnostic only; no duplicate replay parser or split algorithm. No actual member reading/decoding/extraction in this feature.
Delta is signed second minus first in exact selected unit. Since each value is bounded to [0,INT64_MAX], signed subtraction is safe including both extreme signs. Positive/negative only describes larger/smaller duration/count; no automatic winner/record/eligibility classification. Preserve null vs zero. No cross-domain subtraction, ratios, rankings, trend fitting, arbitrary timeline or sector interpolation. Future explicit coverage, split/telemetry contracts and actual runtime evidence required.
