## Integration blockers and contract differences, ordered by dependency
INT-01-A (BLOCKED, G1/G2/G3): capture identity/clock/owner transport and native source/writer lifetime. Start dependencies before backend lanes; stop acceptance, orchestrator shutdown, backend cooperative shutdown/join off UI/loader lock, drain notifications, take reports and persist terminal outcomes before releasing Store/factory/clock/target dependencies. Poll terminal mailbox and report slots independently. Do not equate a sealed media marker or finalized Worker with complete run. Preserve BackendEnd reason, actual Worker state, boundary and counters, plus immutable accepted Session evidence in later persistence. Existing Orchestrator intentionally retains only partial terminal fields; do not extend shared contracts without A coordination.

INT-01-B (BLOCKED, G4): explicit size mismatch. OutputIdentity permits 1..64 GiB budget, evidence_inventory.MAX_BYTES 16 GiB, evidence_archive.MAX_TOTAL 1 GiB aggregate with separate physical ZIP bound. Valid staging budget/final marker does not guarantee export fits. Require preflight using actual verified sizes plus bounded manifest/ZIP overhead; return explicit unsupported/oversize and preserve original recording. No automatic trimming, splitting, recompression, deletion or quota promise; larger-format strategy needs separate design. This is a source-backed compatibility limit, not a newly reproduced failure.

INT-01-C (BLOCKED, G4): nonlocal index/transport gap. Establish same trusted database identity for lookup/insert/readback, explicit serialized owner and bounded selection-token resolution. Do not use raw manifest origin, C++ token as path, or arbitrary JSON as typed projection. Reuse existing project bytes and native bridge; prove field/enum/null/zero mapping and exact whole-container identity. Legacy unguarded admission intentionally differs from opt-in guard; never silently fall back. No general adapter changes under this audit. Request A coordination for a bounded real native-index fixture on Windows, including unavailable DB and lost acknowledgement, no real user import. No claim of crash durability or hostile races.

INT-01-D (BLOCKED, G4/G5): member safety. The current verifier structurally permits inert payload.exe diagnostic member; B-EXP-02 test deliberately documents this gap, B-VAL-01 reports review only. A-0020 accepted guarded exchange solely under trusted private/quiescent scope, not arbitrary untrusted import. Explicit allowlist/version policy, parser isolation with resource limits, Windows path/reparse/ACL and privacy review must precede untrusted import or playback. Exact re-export cannot sanitize private data. No shared member policy change here.

INT-01-E (PROPOSED maintainability): runtime optionality vs source removal. analysis/comparison.hpp includes playback/planner.hpp for Member shape, which includes archive_exchange.hpp; recovery_view.hpp includes recorder/persistent_output.hpp for staging read models. Public dependencies, no observed cycle in these reviewed includes, but deleting those whole headers while retaining consumers fails source compatibility. Keep runtime disable via absent ports; if physical removal required, propose moving only minimal identity/inspection contracts to narrow independently owned public headers with compatibility includes and existing test regressions. No new central manager, duplicate schema or speculative extraction/refactor in this audit. A review needed before any shared contract move.
