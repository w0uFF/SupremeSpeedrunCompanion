# B-REC-01 — Recorder application orchestration (offline candidate v1)

## Module boundary

Recorder application service: public/orchestrator.hpp, header-only C++17. Depends on the public recorder Worker state/stats/quality, capture_boundary Ledger and session Event/AttemptState contracts; no private engine dependencies. No shared contract change. Backend is a feature-owned injected command port, not a native ABI, and is not yet implemented by the production media adapter. No UI, files, configuration, database, archive admission, decoder, native capture, overlay rendering or submission authority is introduced. Omit the header/test to disable; no bootstrap registration.

## Commands and ownership

One serialized owner calls all methods. Backend start/stop/cancel enqueue bounded commands, must not wait, perform I/O, call back synchronously or throw. A start acceptance means a backend owns cleanup and will eventually deliver one terminal completion; rejection owns no resources and emits no callback. Caller retains backend lifetime, routes its completions to the owner, and must call shutdown then drain completions and take reports before destruction; backend owns its worker threads and joins outside game/UI callbacks. This contract is not a hard real-time guarantee (bounded vector allocations on open, bounded linear scan). Allocation failure at open must be handled by the future composition root; no backend starts before slot allocation.

Capture ID is a strictly increasing nonzero instance-local token allocated by the owner. Opaque target ID is nonzero and must map to an explicitly approved game-window target in a future adapter, never desktop/microphone by inference. The owner must not reuse session/attempt identity across distinct attempts, and must supply a fresh capture token only for a genuine new recording command. These tokens are not serialized global archive IDs. All boundary times use the existing Session monotonic milliseconds epoch; the future adapter must establish correlation to capture timestamps before using them. No independent timer is started or recalculated here; Session/timing own race clocks.

- prepare(capture,target,{session,attempt},ms) is an automatic pre-start request, not an engine event. acquired(capture,ms) is an actual acquisition-boundary notification, not just Worker ready. If the accepted start event arrives before acquisition notification, or acquisition time is not strictly before start, the report is incomplete. No retrospective fabricated marker.
- event(capture,session::Event) consumes only already accepted Session events (never raw engine observations). It preserves existing attempt identity/sequence; it does not call Session::consume a second time or duplicate its track/IGT validation. The caller filters session-wide abandon/victory (attempt_id=0) and routes relevant automatic interruption separately. Wrong capture, wrong bound attempt, stale sequence or decreasing timestamps are rejected; start is never implicitly triggered by a reset. Race finish records the marker and leaves capture running.
- result_visible(capture,identity,ms) is the observed result boundary; automatic recording requests stop through that timestamp. The backend must continue acquisition until the boundary is reached, drain accepted packets and finalize via existing Worker; if impossible, report boundary not reached/failure. This is not proof that a decoded frame shows official IGT or full race coverage. Manual recording remains active across results, resets, restarts and different sessions; selection() records observed selection only, not verified menu proof. Manual stop is explicit. Auto requests while manual recording owns capture return busy; producer routes accepted events into that existing manual capture.
- A true restart ends the old automatic capture with an incomplete report and the next prepare uses a fresh token. A reset only advances accepted event sequence. interrupt() handles automatic exit/restart before start or before result visibility; it is capture interruption, not a fabricated race end. Manual stop mid-race preserves the last actual race state as racing and marks ledger capture segment abandoned (truncated). Missing result before another manual attempt marks the session incomplete.
- Up to four outstanding slots (one active, others closing/terminal). New capture may be requested immediately after stop/cancel command without awaiting previous finalization; backend can reject if resources unavailable. No unlimited workers are implied. Terminal reports occupy their slots until explicitly taken; saturation returns busy without overwriting evidence. At the existing 128 marker cap, the manual session explicitly stops incomplete on a further start and caller must offer a new capture; no silent marker omission. Busy/unavailable/rejected must be surfaced by the future controller/view.
- completed() receives consistent terminal Worker stats/quality after backend cleanup, plus stop-boundary acknowledgement. It rejects nonterminal/duplicate/wrong IDs. No known orchestration failure (incomplete=false) is not a coverage, decoded-media, audio, integrity or eligibility assertion. Finalized can coexist with incomplete; cancellation requested during finalization cannot retract a completed backend write and must remain incomplete. Explicit worker failure, cancellation, missing boundary/video or aggregate loss/invalid/discarded/unwritten packets mark incomplete. Quality retains handoff gaps separately; no uncalibrated threshold or proof claim. Reports are in-memory only and must be moved to a later persistence layer. No silent deletion or retention decisions.

## Decisions, integration and validation

Feature-local port is a reversible application seam, not a competing shared race event schema. GPT A owns native event production, clock correlation, shared interface changes, root CMake/CI and wiring. The next media task implements the actual injected backend with existing Worker, lookahead/timestamp helpers and reusable sink, after review; no duplicate acquisition experiment. Missing completion can hold a bounded slot indefinitely: backend timeouts/cleanup and crash recovery remain unresolved before production. No physical capture, actual audio, device loss, menu proof, real game or Windows runtime verified. G1 and audio blockers, COMMUNITY-001, DEMO-TRACK-01, existing rules, optionality and manual fallback unchanged.
