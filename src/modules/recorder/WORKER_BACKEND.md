# B-REC-02 — Worker-backed video adapter (offline candidate v1)

## Boundary and decisions

New feature-local public/worker_backend.hpp implements the existing recorder application Backend. It uses the actual unchanged Worker, Sink, FrameLookahead, TimedFrame, StreamQuality and qpc_to_100ns primitives. The factory is injected; there is no WGC/Media Foundation binding or native activation. No fixture, shared contract, root CMake, version, CI, storage format or competition rule changes. The existing MF fixture sink was inspected, not copied or edited. No audio stream, recorded overlays, media file creation, decoding, persistent recovery, or global archive identity is implemented by this increment.

Two fixed capture lanes are created during backend construction outside game/UI callbacks. Each accepted capture has one reserved request, sticky cancel bit, first valid stop-through command, acquisition mailbox and terminal mailbox. Each lane owns its FrameSource and one Worker; the worker exclusively invokes Sink begin/write/finalize/abort. The factory is borrowed and must outlive the joined backend; it must be safe for concurrent open calls, verify immutable target identity and the common clock epoch, reserve a unique destination, and retain a generation-specific target lease until source destruction. It must reject an unavailable target rather than silently substitute another window, desktop or microphone. A future native adapter must demonstrate target close/replacement and timebase correlation before activation. Neither the synthetic factory nor these tests prove those properties on Windows.

Owner-thread start/stop/cancel/poll/shutdown use only a short mutex-protected bounded mailbox operation; no factory call, encoder work, join, or synchronous callback. start returns false for unavailable capacity, invalid/stale capture token or shutdown; a rejected request owns no resources. Valid stop/cancel for an accepted active ID never competes with frame queue capacity; stop records the first through-ms, cancel is sticky and takes precedence. Unknown/stale/terminal IDs and duplicate commands are ignored. Cancellation is linearized against terminal publication, including during non-interruptible finalization. Completion carries separate application disposition, actual optional Worker terminal state, BackendEnd reason, aggregate/per-stream counters and queue high-water. Acquisition precedes completion within each lane; inter-lane ordering is not guaranteed. Poll routes Acquired to Orchestrator::acquired, Completion to Orchestrator::completed using state/stats/quality/stop_boundary_reached. Keep the full Completion for later persistence/view; the orchestrator presently retains only its existing report fields and consistency flag. No callback or separate race event schema. A lane remains reserved until its terminal notification is polled, even if cleanup already completed; missing polling cannot overwrite evidence. The orchestrator independently retains reports until taken. A backend rejection may surface as unavailable even when the application still has a free report slot.

Two lanes permit a new recording while one finalizes. This is a deliberate conservative bound, not a guarantee every immediate restart can be recorded; a second simultaneously draining job can exhaust capacity. Queue defaults 8 slots x 2 MiB per lane, max 32 MiB queued per lane (64 MiB combined), exclusive of one in-flight packet, lookahead/source buffers, encoder/platform allocations and container overhead. Frame capacity is checked before handoff; overflow/invalid/closed offer fails closed rather than retrying, blocking the game or retiming. Real capture source buffers and sink resource budgets are future requirements. No measured game-performance or hard real-time claim.

## Clocks, boundary and cleanup

FrameSource::read(budget) returns frame/idle/end/error and must return within its 5 ms polling budget; it owns its source resources and runs only on its lane. TimedFrame.time is 100 ns from the same supplied epoch as Session monotonic_ms (floor(time/10000)); session_time_100ns reuses exact QPC conversion and rejects mismatched frequencies/pre-origin/unsupported or overflowing values. No native source clock correlation is inferred. First valid frame observed after request, not just Worker readiness, emits acquisition timestamp; a stale pre-request frame is rejected. Owner must poll before accepted race start to avoid a conservative incomplete classification. Stop-through requires at least two valid frames and an actual frame in a strictly later millisecond than the requested boundary (equal truncated ms cannot prove ordering); that frame is flushed as the existing 40 ms nominal terminal packet, with prior durations using existing capped 100 ms lookahead. Only successfully finalized Worker output with accepted tail and no prior cancellation acknowledges the stop boundary. This does not establish that the frame shows official IGT or complete decoded evidence. Late cancellation may retain actual finalized Worker state but clears acknowledgement and prevents complete classification.

Factory/open/Worker readiness, absence of frames and stop-through acquisition have separate configurable steady-clock deadlines (default 5 s each, range 1..60000 ms), independent of race timestamps. These are provisional operational limits, not calibrated gameplay/verification thresholds. Factory and source calls must cooperate; deadline checks cannot interrupt an already blocked method. Source is released before drain/abort, then Worker is stopped/cancelled, polled to a terminal state and joined on the lane, stats read only after join, Worker destroyed before Sink. Terminal publication follows both source and sink destruction. No fabricated cleanup acknowledgement. Worker failure, source end/error, invalid frame, deadline, rejected offer and cancellation remain distinct; no silent deletion. If begin/write/finalize, factory or source destruction never returns, cleanup and join may remain pending indefinitely. Reserved lanes remain unavailable; no detach, unsafe thread termination or claimed success. shutdown marks all pending commands cancelled; join and destructor are explicitly blocking composition-root operations outside loader lock, UI/game frame and callbacks; terminal mailboxes remain readable after join until polled. Before production, require cooperative native deadlines or process isolation and persistent incomplete recovery. This is a known readiness blocker, not an assertion of liveness for a hung codec.

Existing FrameLookahead is intentionally unchanged and retains its fixture limit of 1440 frames / 90 seconds, strict sequence and fixed nominal duration policy. This candidate therefore cannot support arbitrary-duration manual sessions or real championship recording. Bound exhaustion fails closed; B-REC-02b must replace fixture-only bounds with reviewed production duration/retention policy while preserving fixture behavior, and prepare reusable real media sink independently of A-owned fixtures. Do not enable capture using this adapter yet.
