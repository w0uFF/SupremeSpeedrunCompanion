## Proposed decision
Introduce a recorder-owned value-only terminal projection with explicit versioned codec, after approval. Keep old typed Journal/retain/recover available until a coordinated successor is tested. Do not implement existing Journal by fabricating a Report or Ledger. Instead project live terminal Snapshot only after existing assemble revalidation; decoded projection is a historical observation, never a live state machine. Refactor validation/equality toward a single public-value predicate shared by live projection and decoded view, with strict decoded-domain checks; preserve existing valid handoff behavior/tests. No new database, generic framework, dependency on UI, OS or native engine in the value/codec. One narrow storage adapter for terminal projection, reusing existing private filesystem mechanics where semantics match. Composition outside frame/loader callbacks; borrowed allocator/store dependencies live through completion and explicit retry. Disable by omitting port, retain original snapshot and expose unavailable, no change to gameplay.
Alternatives considered: raw C++ serialization (reject ABI/private-state hazards); reconstruct Ledger through synthetic events (reject invented history); reuse synthetic phase JSON (reject mismatched authority/fields and manual scope); extend SQLite now (reject shared schema changes and unnecessary second admission path). A private bounded append-only record best fits current scope. A future unified private attempt context may require separate reviewed migration; no commitment to permanent wire compatibility before approval.

## Candidate value contract (reviewable field map)
Use full values, not hashes alone. The mapping below must preserve every field in same_snapshot. Redundant live public fields may be stored twice as proposed to check equality, not recomputed from later metadata.

| Group | Required values and units |
|---|---|
| Binding request, report request | capture, target, mode, optional paired numeric session/attempt, requested_ms. Exact equality. Target is historical opaque ID only, never a window handle usable after restart. |
| Binding output | capture, token (32 lowercase hex), byte_budget (existing OutputIdentity.valid). |
| Binding attempts, ordered 0..128 | identity.session, identity.attempt, run_id, session_id (opaque lowercase32 hex). Automatic exactly one including rejected pre-start; manual exactly report count. |
| Report | acquired_ms?, stop_boundary_ms?, stop_boundary_reached, incomplete, terminal_stats_consistent, terminal State. Preserve raw consistency flag even if false; never silently normalize counters. |
| Report stats | accepted, written, dropped_full, rejected_invalid, discarded. |
| Report quality, exactly video then audio | written.packets/duration/first/end, accepted, dropped_full, rejected_invalid, discarded, dropped_duration. Coverage times 100 ns, not Session milliseconds. |
| Report attempts, ordered 0..128 | identity.session, identity.attempt, start_ms, sequence, state, marked, selection_observed, end_ms?, result_ms?. |
| Ledger public projection | id, state, observed_menu, ordered markers 0..128 (run_id numeric session, attempt_id, start_ms, end_ms?, End?). Preserve marker names/semantics, not private state. |
| Completion optional | capture, BackendEnd, application State, actual worker_state?, high_water, stop_boundary_reached, full stats and exactly two full qualities as above. Absent completion stays absent. |
| Accepted observations, ordered subset 0..128 | full AttemptKey, Attempt.id, started_ms, typed Track, AttemptState, end_ms?, igt_ms?, resets, independently supplied rta_ns?. No conversion or guessed result. |
| Media observation | Status, claimed OutputIdentity?, observed_bytes?. Preserve incomplete oversize bytes without clipping to budget. Finalized_claim positive size <= budget. |
| Handoff disposition | reconciled/incomplete only, as assembled. review_required is refusal, not a fabricated snapshot; caller retains raw inputs. |

Every ID/counter/time uses explicit uint64 domain where existing type does; accepted IGT/RTA constrained to INT64_MAX, resets <=1000000, high_water <=128. Booleans exactly true/false or canonical 0/1 on wire; missing independent values distinct from zero. Stable enum spellings explicitly mapped from actual Track, Mode, State, AttemptState, Ledger State/End, BackendEnd, staging Status and Disposition; no raw C++ ordinal casts on disk. Request numeric attempt optional is a pair, not two independent nullable numbers. Report and completion quality carry separate raw values even when equal, verify matches. Count limits before allocation, exact order and membership, known finite enums, exact optional tags and no unknown fields. Validate duplicated request/output/key/accepted fields and current assemble rules. Additional decoded safety checks (marker count/identity/order and public state domain; no unsigned subtraction on invalid coverage; preserve incoherent counters only as incomplete diagnostics) are separate review items: trusted live Report may contain incomplete evidence. A stricter disk decoder must never reinterpret a failure as a success or discard the original bytes. Recompute disposition using a shared pure public-value validator, reject inconsistency; never trust a stored reconciled label alone. An apparent well-formed record is still historical, untrusted as authority. No settings/clock semantics/build/profile fields invented; those remain separately bound by future approved context. No path, username, process pointer, handle, arbitrary text, game asset or media bytes in projection.

## Candidate encoding and bounds (not yet implemented)
Propose canonical ASCII positional records, using existing bounded decimal conventions (staging::number and std::from_chars) rather than introducing a general JSON parser or a dependency. Header SSC-TERMINAL-1 followed by LF. Each fixed record tag and exact field list in table order, single ASCII space between fields, LF including final line. Canonical unsigned decimal 0 or nonzero leading digit; optional scalar '-' for absent; paired optional identity either two '-' or both values. Token/ID exactly32 lowercase hex; enum spellings fixed lowercase; no escape syntax, CR, NUL, comments, trailing whitespace, extra records or unknown versions. Counts explicit immediately before repeated groups; completion presence tag before conditional fields. Use fixed video/audio order; validate count before reserve/read. Serialize the full projection deterministically; require decode followed by encode byte equality (including terminal LF), not just semantic equality. Never dump object memory, padding, std::optional layout or size_t. Candidate maximum128 KiB, 512 bytes per line, <=128 rows for each of keys/attempts/markers/accepted, fixed remaining records. Conservative field-count estimate per row <128/192/128/320 bytes respectively; 128*768=98304 plus <16KiB fixed records, below128KiB. Review exact grammar, maximum populated golden fixture and UINT64_MAX edge tests before locking version. Bound read to maximum+1, reject zero/oversize before parsing, no recursive grammar or unbounded string allocations. Existing 128-byte media markers and 1024-byte synthetic archive journal stay unchanged. Byte equality is structural, not authentication or protection against same-user tampering. Unknown version or corrupt record stays read-only review, no silent migration.

## Storage and explicit recovery plan
Propose existing explicit private fixed-volume terminal journal root, distinct from staging/game/Imports/Exports/index; token-derived fixed names <token>.terminal-v1 and <token>.terminal-v1.partial under root. Rejected starts may lack a media slot, so not inside the media token directory. Only explicit allocated token lookup, no directory scan. No arbitrary user paths from persisted values. A bound private root/allocator attests ownership. The terminal adapter needs global token and run-ID ownership (within binding validation is insufficient); require caller-owned durable reservation/allocator port to verify each run_id and token belongs to exactly this capture/attempt mapping, including cross-capture session scope. Do not create a second ad hoc ID database or infer uniqueness from random ID alone or the terminal filename. For initial isolated fixtures inject exact reserved mapping; missing/unavailable allocation refuses write. Real allocator/reservation and crash-before-terminal mapping are separate blockers, not implemented by this proposal. Reserve IDs before accepted observations in future owner workflow; never reuse IDs after failed start, incomplete output or crash.

Reuse recorder FilesystemStore path/regular-file/exclusive-create/flush mechanics through narrow feature-private helper only after A approves exact extraction; preserve 128-byte marker behavior and tests. Reuse synthetic_journal_store/ archive_publish no-replace same-directory publication protocol, not their schemas or unrelated Python execution. Trusted serialized quiescent owner, POSIX owner-only permissions and fixed private Windows ACL configured by caller, check all ancestors/root, no symlinks/reparse/network/unsafe roots, regular files and physical identity/link counts. Use existing exclusive creation/FlushFileBuffers or fsync; no replace or truncation of any existing file. Hardlink publish (CreateHardLinkW / link) only where supported; refuse otherwise, no unsafe copy/rename fallback. For regular single terminal/partial require single link, alias pair exactly two links and same physical identity plus exact bytes; separate files even if equal remain conflict. No claim of hostile race/ABA resistance; use opened handle identity and recheck, no concurrent mutators outside serialized owner.
Explicit append/retry: validate projection and reservation, inspect final+partial; if both absent, create partial exclusively, write exact bounded bytes, flush, close, verify byte/readback and ownership. Publish no-replace hardlink; verify same-file pair and bytes; flush directory metadata where supported (POSIX); remove only owned exact partial alias on explicit append/retry after verified final, then recheck final bytes and identity. On Windows directory-entry power-loss guarantee unavailable; report process-interruption semantics only. Failed write/flush/publication/readback leaves prior bytes intact, no automatic cleanup of torn data or retry. A returned acknowledgement requires exact final readback and no unresolved alias. Exception after effect remains uncertain; caller retains original even if final now matches. An explicit later retry can classify unchanged after independent complete readback, with no duplicate effect. No auto retry on startup.

| Observation under quiescence | Action, only on explicit command |
|---|---|
| Both absent | Unavailable/missing if recovering; new append only with valid live desired projection and reservation. Never reconstruct from media. |
| Exact valid pending only | Review on read; explicit same desired and reserved retry can flush and publish. |
| Torn/unsupported/unreadable pending | Review; retain bytes; no overwrite, deletion or resume. |
| Exact valid final only | Read-only matching historical record; identical explicit retry unchanged, differing request conflict. |
| Final and exact same-file pending alias | Report pending-alias review; explicit matching retry can remove owned alias, not final. |
| Separate files, mismatched bytes/identity, unknown version, bad link count, missing reservation | Review or unavailable; no effects. |
| Retained record and matching fresh staging status/identity/size | Matching claim or incomplete as originally classified; no promotion, same-size mutation not detected. |
| Retained record and changed/missing/corrupt staging | Changed_or_review, preserve both, no repaired snapshot. |
| Nonquiescent or optional store unavailable | No mutation, no fabricated absence or result. |

Read-only inspection must distinguish missing, pending, committed, alias, conflict/review and unavailable; old Journal optional find cannot express pending distinctly. Propose narrow successor read/append port with typed inspection/result and one explicit retry; existing in-memory Journal stays compatible. Reuse current retention failure semantics; preserve input until returned acknowledgement plus exact readback or explicit identical retry. Implement no archive creation/index insert, local admission, real recovery catalog scan, untrusted import, parser for video/replay or actual native runtime.
