# B-REC-02b — Extended timeline and owned video sink (offline candidate)

## Decisions and scope

Generalize the existing recorder-owned FrameLookahead rather than create a parallel algorithm. Existing constructor calls, public fixture max_frames/max_span, 1440 selected frames, 90 s selected timestamp span, 100 ms hold and 40 ms terminal tail remain unchanged by default. WorkerBackend gains an immutable validated BackendLimits::timeline; the composition root can explicitly choose LookaheadPolicy::extended(). No source or fixture changes under tools/media, no change to shared contracts, Worker, Sink, TimedFrame, original test sources or queue limits.

Extended preset: at most 3,000,000 selected frames, 6 h timestamp span from first to last selected frame, plus explicit terminal hold; customizable lower bounds, positive hold at most 1 s and positive tail no greater than hold. This ceiling supports ordinary individual runs and prospective longer sessions without storing the recording in memory. It is a provisional engineering bound, not an approved competition rule, tested encoder capacity or recommended user setting. Frame memory remains one pending lookahead plus caller/returned packet; Worker queue and source/codec allocations are separate. Invalid/expired frame count/span still fails closed through existing invalid_frame result. No retiming, gap filling or fabricated tail. Six-hour span is a media timestamp bound, not a hard wall-clock watchdog; stalled/noncooperative codec calls remain B-REC-02 limitations. Manual marker cap remains 128; championship session-wide grouping remains pending. No native activation.

## Owned video sink boundary

public/owned_video_sink.hpp is a reusable decorator of the unchanged Sink interface, not an encoder implementation. Inject an OutputProvider and immutable OutputIdentity (nonzero instance capture token, 32 lowercase-hex opaque independently allocated output token, positive byte budget <=64 GiB) and VideoFormat (even NV12 dimensions 2..4096, packed payload <=16 MiB, nominal FPS 1..120, bitrate 1..100,000,000). These limits are configuration guards, not supported Windows codec specifications. Provider must outlive WorkerBackend and all workers; concurrent reserve calls must be safe. The composition root/factory binds the identity to the exact Request.capture and retains a private mapping for terminal reporting; the opaque token is not a filesystem path, global run ID or local provenance. Format and byte budget are copied before work begins. No file or directory operations in the decorator, no path exposure or upload.

On Worker thread reserve an exclusive output lease; reject null/collision/mismatched identity before writer creation. A provider is responsible for atomic no-overwrite reservation, safe private root, generation ownership and cleanup or recoverable reservation on throw/mismatch. Mismatched identity is released without mutating its state. On that same thread create and begin the injected codec Sink, validate video-only packet shape and nonoverlapping signed-64-compatible timestamps/duration, pass exact PTS/duration (gaps retained), and observe output size after begin/write/finalize. A byte-budget exceedance or unavailable size fails closed; it is an observed-size guard, NOT a hard disk quota: writes/codec buffering may exceed between checks, and a concrete provider must implement bounded disk reservation/write quota before production. No automatic deletion or silent trimming. This does not impose a physical write limit or authorize storage paths.

Successful finalize destroys the codec before lease seal and destroys the lease on the worker before Worker terminal state. Empty stream cannot seal. Abort after partial begin/write/finalize failure invokes underlying abort once if still owned, releases codec before marking matching lease incomplete and destroys lease. If codec finalized successfully but size/seal fails, do not abort the already-finalized codec; retain incomplete lease. Seal is media finalization only, not run/archive eligibility; late cancellation can still make capture incomplete even if codec output was sealed. Provider must make seal transactional or preserve ambiguous status on throw, incomplete noexcept and idempotent, destructor safe. Reserve/make_writer must handle partial resources not returned to wrapper. Do not call lifecycle directly or destroy while Worker active; wrapper is destroyed only after Worker join. No new thread in decorator. Cooperative cancellation remains Worker-owned; it cannot interrupt blocked writer operations. No hard real-time claim.
