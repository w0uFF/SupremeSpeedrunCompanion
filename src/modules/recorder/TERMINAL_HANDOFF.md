## Boundary and ownership
public/terminal_handoff.hpp consumes existing recorder application Request/Report/Completion, OutputIdentity, staging::Inspection/Store, and session::Attempt. Feature-owned Binding, AttemptKey, Accepted and Snapshot are copied in-process terminal values, not a wire format, ABI or replacement attempt model. Composition owner provides a trusted preallocated immutable output and run/session mapping, actual accepted Session snapshots and full backend notification before discarding them. Automatic binding contains exactly one allocated attempt, even if startup failed before any start. Manual binding contains all observed attempts in report order (up to 128), each with distinct run ID and consistent bidirectional numeric-to-opaque session identity. Missing results are retained as missing, never fabricated. Check capture/target/mode/request time/bound numeric attempt against Report, exact output identity and independently observed staging claim, and exact supplied completion state/boundary/counters/quality. Full Completion retains reason, optional actual Worker state, high-water and all counters. Compare accepted attempt identity/start/end/state and preserve typed track/difficulty, IGT, resets and independent nullable RTA; no timing conversion or inference. Time values fit signed64, zero distinct from absent. Report does not contain track/IGT/reset count or independent RTA, so the producer must supply genuine accepted Session values; the handoff cannot independently verify them. Numeric capture IDs are instance-local, not global identities. Global nonreuse and cross-capture collisions require trusted allocation and journal adapter enforcement; this module checks within-binding collisions, not a global registry.

Caller serializes outside game/render callbacks. No threads, encoding, parser, raw paths, native handle, mutation of session/recorder, or package generation. Retain the full original inputs until explicit verified retention/readback and owner policy permit release. Take terminal reports only after backend cleanup; missing completion (including rejected start) remains incomplete; never manufacture an acknowledgement. Binding and accepted snapshots are trusted owner values, not arbitrary user/manifest input. No cross-store transaction, hostile race or authenticity guarantee. No settings serialization here: existing AttemptBinding retains separately redacted attempt settings; settings/clock semantic/build/profile bindings and approved local admission remain separate gates.

## Disposition
assemble refuses inconsistent request/output/attempt mapping, malformed/stale completion, missing required media identity, contradictory/corrupt media claims and inconsistent supplied results as review_required with no assembled snapshot; caller must preserve raw inputs for review. Coherent but missing/unfinished attempts, missing RTA, missing completion, terminal failure, absent/pending/incomplete media, incomplete report, missing boundary, or cancelled reason even if Worker finalized => incomplete. Entire manual capture is conservatively incomplete when any included attempt is unfinished/restarted/abandoned or lacks evidence; individual accepted results remain unchanged and are not reclassified. For truncated manual capture a ledger abandoned marker is not an accepted race abandon; the accepted state remains racing. A reconciled result means only no known inconsistency within this handoff from trusted inputs: existing Report completeness/terminal consistency flags, final state and boundary, normal stopped completion, matching finalized_claim and accepted finished results with both times. It is not proof of real frame coverage, menu, audio, safe media, actual timing, package readiness, official result, local provenance, PB or eligibility. Does not recompute Report's existing consistency algorithm or inspect raw media; do not pass a manually constructed report as authoritative.

## Explicit retention and recovery
Optional Journal port provides typed find(token) and append_new(snapshot), under trusted serialized owner, globally unique tokens/run IDs, bounded reads and immutable no-replace storage. retain validates desired snapshot again; absent port or preflight read failure unavailable, exact existing public evidence unchanged, different existing snapshot conflict. One append attempt only; success requires returned acknowledgement and exact public-field readback including full Completion, accepted results, ledger public markers and report flags. Any lost acknowledgement or failed/missing/different readback remains uncertain even if matching data may have been written; caller retains originals and may explicitly retry (identical => unchanged). No automatically retried effect, no overwrite or deletion. same_snapshot compares exposed immutable values, not private Ledger implementation memory, raw object representation or cryptographic digest. Adapter must preserve this exact public projection. No concrete persistence adapter: serializing/reconstituting the public terminal projection, rather than replaying fabricated Session/Ledger events or dumping C++ objects, requires coordinated versioned schema and review. Existing synthetic_journal_store.py and synthetic_recovery.py are explicitly synthetic-only archive phase mechanisms; reuse their no-replace/explicit retry principles, not their authority or incompatible format. LOCAL_ATTEMPT_ADMISSION remains proposed; no local index/admission, synthetic journal change or new database. Request A coordination for a narrow recorder terminal snapshot codec/adapter, safe private path/flush/no-replace behavior and crash-point tests before claiming durability. The in-memory fake Journal does not establish persistence or global collision handling.

recover takes a previously retained typed snapshot and explicitly supplied staging Store with caller-attested quiescence. Revalidates prior handoff and fresh existing staging::inspect for the exact output token; same status/identity/size only gives matching_claim or incomplete as originally classified. Changed/malformed media or prior disposition => changed_or_review; absent store => unavailable, not quiescent => no reads. Same-size byte changes are not detected by staging markers. Never reconstruct a missing journal from media, resume recording, repair evidence, publish archive or promote an incomplete handoff. Does not re-open or authenticate a real journal on restart. No archive size strategy/automatic trimming added (INT-01-B remains). No public API or source in existing modules modified.
