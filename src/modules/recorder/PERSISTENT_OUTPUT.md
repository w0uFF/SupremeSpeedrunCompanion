## Private staging schema v1

Explicit existing absolute private staging root, separate from Runs/Imports/Exports and base game saves. One immutable token directory with fixed child names: intent, video.mp4, incomplete, finalized. No path input from on-disk fields or arbitrary filenames. Atomic exclusive directory creation reserves token across cooperating providers/processes, even if old directory empty or corrupt; no reopening/reuse or overwrite. Check free space before mkdir (advisory only). Intent written exclusively before handing out lease. Reserve failure preserves any directory/partial marker; no deletion. One writer creation only; refuse if media path exists or intent/terminal status inconsistent. The codec owns creation and writes; caller must keep staging root private/quiescent except cooperating writers. No hard guarantee against concurrent malicious same-user path substitution or compromised codec. No global path scanning.

Each marker <=128 bytes ASCII: intent is SSC-MEDIA-1 followed by newline, token/newline, canonical unsigned decimal capture/newline, canonical unsigned decimal byte budget/newline. Terminal marker repeats exact intent followed by incomplete/newline, or finalized/newline plus exact observed positive byte size/newline. Reject overflow, leading zero, trailing/extra fields, unknown version, wrong token, malformed/oversize/empty records, mismatching terminal identity/size, both terminals. Files are append-only exclusive creation, never replaced. Direct write may leave torn marker, classified review_required, not repaired. No cryptographic authentication/hash or decoded-media proof; same-size tampering is not detected. Marker bytes are claims even under private root. No archive metadata can grant local authority.

On Worker: reserve slot and persist intent; create injected writer; existing OwnedVideoSink observes size after begin/write/finalize and enforces configured per-output budget after writes. After writer finalized and destroyed, Lease requires matching pending intent, positive size <= budget, flushes media, rechecks size, creates finalized marker and flushes. Seal is not attempt finalization, archive, eligibility or proof of coverage. On abort/failure, best-effort media flush and incomplete marker (noexcept, idempotent in memory); preserve pending/review if storage unavailable. If seal acknowledgement lost and both markers present, review; if incomplete marker also cannot persist, a matching final marker can still be observed as a claim, never proof of successful Worker acknowledgement. A lease dropped without seal marks incomplete; partial reserve failure before lease exists remains pending/review. Late cancellation may leave sealed media but incomplete capture; actual Worker/Orchestrator disposition remains separate.

adapters/filesystem_output.hpp implements Store using fixed names and native exclusive mkdir/CreateDirectoryW; O_CREAT|O_EXCL|O_NOFOLLOW or CREATE_NEW with write-through. On Linux use file fsync plus directory fsync after mkdir, marker writes and media flush; tests exercised actual calls, not power loss. Windows uses FlushFileBuffers and checked handles, directory-entry power-loss persistence not established (no directory flush); Windows build/runtime not tested. Reject nonabsolute, root-only, dot/dot-dot, NUL paths; check root ancestors and slots for links/reparse points, fixed drive on Windows, owner-only root/slot permissions on POSIX, regular single-link files. Windows ACL privacy must be established by caller; junction/reparse and hardlink safeguards are source-only until Windows tests. No hostile concurrent path guarantee; no recovery reads while other process writes the same slot. Filesystem failure propagates on writes; inspect maps unreadable/unsafe paths to review. Paths and metadata stay local. Existing read/flush/write operations are off game/UI thread, can block; no hang isolation.

## Recovery

Explicit token inspect, no mutation, promotion, resuming or deletion. Restart inventory must be quiescent (all workers joined, no other writer). Status absent: no slot; pending: valid intent, no terminal, may retain media; at quiescent startup treat as interrupted/unresolved, not resumable; incomplete: exact incomplete marker; finalized_claim: exact final marker and matching positive size within budget; review_required: missing/corrupt intent, unsafe/unreadable files, conflicting/torn/mismatching terminal or media missing/changed. Claim identity and observed bytes optional; never instantiate a local run record, PB or export from these values. Repeated inspection of unchanged state idempotent. No global scan/catalog or automatic repair; next run-library read model can consume bounded explicitly supplied tokens. Unknown extra files are ignored, never opened or removed. Per-token operation bounded metadata and paths, no full-media read or directory scan. No total disk/retention cap or enforceable hard quota; available-space check may race, codec may exceed observed budget before checking. Actual durable power-loss, Windows ACL/reparse handling, cross-process contention beyond atomic directory primitive, aggregate disk reservation and production cleanup/recovery policy remain gates. No silent deletion.
