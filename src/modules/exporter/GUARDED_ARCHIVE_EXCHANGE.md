# B-EXP-02 — Guarded archive exchange (offline adapter candidate)

## Scope and dependencies
A-0017 authorized only the optional guard extension of tools/index_archive.py (baseline 50c42bd39c1627a45adb36123f5b66e0689fb609) after B-REC-03c, plus feature-owned files. A-0018 retains that handoff. This is an offline Python adapter candidate, not a connected C++/native/UI implementation. Reuse existing checked/project/stream_digest/copy_new/publish/inspect and the existing nonlocal projection format. No second parser, hash implementation, database or archive format. No extraction, execution, submission, local admission, PB eligibility or change to evidence member acceptance. Existing archive publisher, verifier, inventory, manifest, status and CLI behavior remain unchanged.

## Guard contract
Optional keyword-only expected_projection (the exact nine-line existing project() bytes) AND expected_container (exact bounded byte count, lowercase SHA-256). Both absent retains legacy manifest-digest dedup; one absent, malformed or unequal rejects. Whole-file identity uses existing stream_digest with physical length bounds and stat/fstat checks, and a second whole-file read around checked(). Guard source before admission and copy, pending/final before publication, each publication callback including recovery alias, source and final immediately before index insertion. No fallback to manifest-only identity in guarded mode. Guarded retries require original distinct external selection; legacy managed-path retry remains available to existing callers. A same-manifest repack is NOT the same physical archive. A digest is identity evidence, not provenance or content safety.

Feature-local tools/archive_exchange_adapter.py exposes immutable Identity and Slot values, selected/managed/destination read-only inspection, admit_import and publish_exact. Composition root supplies trusted absolute paths, one serialized owner, private quiescent directories, bounded protected file list (including original/reference files and index), and paired lookup/insert callbacks bound to the same index. No path from manifest, no opaque UI-token mapping yet. Ordinary import is always imported, regardless of manifest claim. Export accepts only imported/synthetic projections with finalized identical index readback. Compare complete prior slot plus exact freshly observed projection and container, and recheck row before effects/insertion. Index and filesystem not atomic together. Exceptions from effects mean uncertain outcome: refresh readback, explicit retry only. No automatic retry, evidence deletion, overwrite, rollback of committed archive, or index mutation on export. Existing publisher may remove its own partial alias only. Final+pending same-file alias recovery allowed only in managed import under exact two-link pair; separate or corrupt partial preserved for review. Export aliases always review. A finalized archive with missing index can be explicitly retried; indexed orphan or pending archive requires review.

Path boundary: reject relative paths, parent traversal, linked/reparse ancestors, nonregular files, unexpected hardlinks, selected source aliasing protected files or managed archive, managed paths as external destination, Windows unsafe names/streams and non-drive paths. Source and final/partial checked against protected files. These checks are for trusted, quiescent private directories only; lexical drive shape does not prove physical drive type or filesystem properties. No adversarial TOCTOU/ABA, competing writers, systemwide locks, mount substitution, cross-store transaction or power-loss durability guarantee. Multiple bounded full reads intentionally favor verification over performance; no game-thread calls, no large-archive benchmark yet. Actual Windows path/reparse, NTFS, native SQLite binding, interrupted-process durability and C++ port mapping require separate validation and review.

## Proposed future member safety policy (NOT enabled)

Timing and telemetry: exact versioned formats and fixed semantic role/size/record bounds, no arbitrary executable data. Diagnostic: explicit registered bounded names and versioned inert formats, e.g. the existing attempt-settings.json validator, never generic trust in a diagnostic role. Reject executable/script/library content and unexpected names under a separately approved policy; suffix/signature heuristics neither prove malware nor prove safety. Opaque/unknown data and privacy-sensitive data require review. Versioned structured rejection taxonomy proposed: unsupported policy/format, malformed, resource_limit, unsafe_path_or_member, identity_conflict, unavailable, review_required, privacy_review; only actual observations justify classification.
