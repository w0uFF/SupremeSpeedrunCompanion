# B-INT-03 — Read-only archive size preflight

Status: implemented, VERIFIED_AUTOMATED Linux portable tests; optional caller binding and Windows validation NOT_RUN. Addresses INT-01-B size compatibility, not G4 admission or larger archive policy.

## Source-backed limit and decision
Existing recorder OutputIdentity permits up to 64 GiB per output budget; evidence_inventory.MAX_BYTES is 16 GiB per file; evidence_archive.MAX_TOTAL is 1 GiB aggregate payload, MAX_MANIFEST 64 KiB, MAX_DIRECTORY 128 KiB, physical bound MAX_TOTAL + MAX_MANIFEST + CHUNK (1 MiB overhead), 1..64 payload members. Schema 2 optional attempt-settings.json has separate 8192-byte limit. Existing evidence_archive.create calls inventory (which streams/hashes selected files) before aggregate-size refusal. This independent optional tool can refuse earlier with no payload reads. Do not change the limits, existing create/verify/inventory or publish, local admission, member policy or storage retention. Large recordings remain intact; no trim, transcode, split, delete, silent omission or automatic export. Future larger-format decision requires separate review.

## Interface and dependencies
tools/archive_size_preflight.py inspect(root, selected, *, metadata=None) returns immutable Result(state, payload_bytes, manifest_bytes, container_upper_bytes), integer bytes or None. Same explicit name-to-role mapping and optional metadata as existing writer. Trusted owner supplies closed, quiescent staging; no arbitrary untrusted import, no directory scan, no actual export or destination selection. Use existing safe_name, ROLES, linked and inventory limit; root and explicitly selected files only, regular file sizes via stat, at most 64 names. Existing root/leaf link checks, not new ancestor/hardlink/ACL policy. Missing/unreadable metadata observation unavailable; not proof of content readability. No opening, hashing, writes, paths in Result, persistent state, native calls or background work. Run outside game/UI callbacks. No hard real-time or filesystem race guarantees.

States: invalid_selection, unsupported_source, unavailable; inventory_file_too_large, archive_payload_too_large, settings_member_too_large, invalid_metadata, manifest_too_large, container_bound_unavailable, within_size_limits. Validate selection then observe all sizes, then per-file, aggregate and schema-2 settings size limits, then metadata/manifest/container. Unavailable observations do not fabricate totals. Zero is a real observed size, not None. Schema-2 metadata validation reuses run_manifest.build; schema-1 uses the existing writer's shape. Fixed-width 64 lowercase ASCII zero placeholders only compute serialized length; never returned as a digest, persisted, or claimed as verified. Same JSON serializer arguments as writer; matching selected sizes/names/roles/metadata yield same manifest length regardless of actual lowercase hexadecimal digests. Unicode escape lengths included. Existing settings-content/name/role verification, content safety, media validity, actual file hashes and provenance remain independent checks. A schema-2 size refusal can precede full metadata validation; no claim that accepted shape proves safety. Schema 1 unchanged.

Container bound is specific to current seekable ZIP_STORED writer with ASCII names, no archive comments, classic central directory, local ZIP64 payload headers. At current bounds (65 total entries, max127 ASCII bytes per name, payload <=1GiB, manifest <=64KiB), central directory has no ZIP64 size/offset extra fields; estimate central directory as sum(46+name length). Conservative physical upper estimate: total payload + serialized manifest + 22 EOCD + sum(30 local + 46 central + 2*name length + 20 local ZIP64 extra + 24 possible descriptor allowance) over all entries including manifest. Not a generic ZIP estimator; may overestimate. Refuse if directory or physical upper bound exceeds existing verifier limit. Future writer format changes must re-review formula and fixture tests. Import existing limits directly rather than copy numeric limits. No free-space reservation, measured runtime performance, content safety or archive readiness claimed.

## Consumer and failure contract
Independent optional read model: future owner calls inspect on exact intended selection before expensive normal inventory/create. For non-within_size_limits, surface reason, retain source and do not invoke creation. For within_size_limits, only a later explicit authorized export intent invokes existing writer and verifier, rechecking size/digests from current files. Stale observation is never permission; actual writer can still refuse and existing partial cleanup/preservation remains unchanged. No automatic retry or fallback. This increment does NOT wire any existing production writer/caller, allocate a journal or make a recording eligible. Adapter is removable by omitting three additions; no schema migration or policy change. Durable terminal journal remains separate pending A approval.
