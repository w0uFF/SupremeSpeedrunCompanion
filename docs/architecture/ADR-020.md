# ADR-020 — Bounded HD own-window fixture and explicit external retry
Accepted for isolated P0 experiments only.

T30 candidate: 240 selected actual 1280x720 NV12 own-window crops, 40s acquisition deadline, same WGC timestamps, one-frame lookahead (explicit byte count), eight-slot payload bound 11,059,200 bytes, 100ms hold cap, 40ms terminal, controlled pause; independent H264 decode count/dimensions/PTS/first luma sample. Uniform dark/bright GDI pattern validated across entire pre-encode crop, not representative game complexity. Report wall/CPU, selected crop conversion and offer latency, final drain, peak/current working set, current private commit, file size and source/crop geometry. Post-finalization output cap16MiB and wrapper timeouts; not a full process memory/disk quota or actual game benchmark. Existing lower-resolution and synthetic A/V tests retained. Synthetic external retry plan binds action, exact immutable journal and resolved directories; reinspection required, one explicit archive publication/alias cleanup or synthetic index insertion, no journal writes. Caller must bind lookup/insert to same trusted database; plan is not independently authenticated DB identity. Native fixture real process termination after hardlink and after native insert; conflicts preserve evidence. No automatic repair, production local authority, native hook, installation, rule changes or release. Expected core43/media6/capture10; Windows candidate pending.

Decision: reuse tested WGC/MF/Worker rather than duplicate capture code or force a desktop resolution change. If HD window geometry/compositor is unsupported, report fixture failure/blocker, not a game result. Keep the existing synthetic recovery coordinator journal-only and make external retry a separate explicit adapter. No new runtime dependencies or schema migration. Preserve validated main until candidate CI review.
