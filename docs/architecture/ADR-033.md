# ADR-033 — Read-only native menu readiness boundary

Status: proposed / candidate, 2026-11-27.

Context: T43 established separate native button/page/sequence registries and explicit sequence dispatch. Exact source provenance for the installed native loader is not established. A visual menu asset is insufficient to authorize a new action. G1 remains blocked.

Options: patch native menu assets now (rejected: no dispatch or runtime contract); expand capture feasibility (not the current bottleneck); bounded read-only observation of exact existing asset and binary references (selected). Reuse existing fingerprint helper and build profile rather than new filesystem traversal or redundant engine classifier.

Decision: new standalone diagnostic with no hooks, calls, install, game mutations or capability activation. No native/proprietary content in repository. All successful reports preserve false provenance/runtime/registration/G1 and empty capabilities. Existing inert DLL and disabled defaults unchanged. Legitimate altered assets are not cheating; observations only. Keep current review/eligibility and no artifact policy. A later independently reviewed installed-disabled prototype requires actual baseline and loader provenance, explicit authorization and rollback. Rollback this increment by removing the diagnostic, test and docs; no production dependencies. Evidence: NATIVE_MENU_READINESS.md, ENGINE_MAP.md, PROJECT_STATUS.md and actual test results when available.
