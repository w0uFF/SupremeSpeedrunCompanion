# ADR-021 — Bound synthetic index identity and longer HD resource series
Accepted for isolated P0 fixture experiments only.

T31 candidate v0.0.22-p0: bind synthetic lookup and insertion through one frozen BoundSyntheticIndex with resolved existing database/bridge path and filesystem device/inode identity. Check both before/after each operation; include bound identity in RetryPlan equality. Reject unavailable identity, final-component symlink/reparse, changed or alternate DB, non-synthetic origin; no authentication, TOCTOU or cross-file transaction guarantee. Ordinary in-place SQLite content changes allowed. Native integration adds two empty database substitution and byte-identical replacement refusal, retains actual child exits after archive link and insert, conflicting origin and journal preservation. Longer actual HD fixture target600 selected frames, same full pre-encode pixel/PTS/count acceptance, 80s acquisition/95s subprocess bounds, 8 slots x1,382,400 bytes, 100ms hold/40ms terminal, separate 240-frame HD and 60/240/600/1200 low-res tests retained. Record samples at1/120/240/360/480/600 selected frames with wall/peak/current working/private bytes and queue high-water; independent parser verifies exact sample sequence and bounds, reports signed private/working growth, not a leak threshold. Existing CI-only display restore retained. Candidate Windows expected core46/media6/capture11, not yet verified. No actual game, production local authority, native hooks or release.

Decision: one explicit immutable port rather than independently supplied read/write callables; filesystem identity is an ordinary single-owner substitution guard, not executable authenticity or adversarial security. No SQLite schema change or production bootstrap dependency. Resource measurements remain descriptive, not performance thresholds; use prior verified HD pipeline and optional hosted-display preparation. Roll back by retaining verified v0.0.21-p0 main until exact candidate acceptance.
