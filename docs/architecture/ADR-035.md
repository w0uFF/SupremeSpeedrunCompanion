# ADR-035 — GitHub Releases for development distribution

Status: accepted owner policy, 2026-11-27; publication implementation review pending.

## Owner-approved release distribution amendment — T45

The owner explicitly authorizes GitHub Releases as the SSC distribution channel for development, experimental, beta and stable builds. Development/experimental builds may be marked pre-release before full native validation, with successful build, exact test status (including FAIL/BLOCKED/NOT_RUN/SKIPPED as applicable), explicit limitations, unique version plus immutable source commit, SHA-256 checksums and release manifest; never present an incomplete build as stable or installable. Beta/stable still require applicable functional/G6 gates and review. This additive policy supersedes historical blanket prohibitions on development pre-releases only; no permission to distribute third-party or proprietary game files, player evidence, credentials, or private data; no authorization to install/hook/replace the loader or change competition rules. No GitHub Actions artifact upload, download or storage under any channel; build/package in runner-local scratch and publish permitted files directly to GitHub Releases. Preserve prior releases/tags/assets; no clobber or overwrite. No license grant inferred.

Existing workflow review: .github/workflows/windows-ci.yml development-release is main-push-only, needs successful core build, explicit SSC_RELEASE_APPROVED=true, LICENSE presence, Release rebuild/test, PE x86 check; packages only offline diagnostic with license/readme, SHA256SUMS and schema1 manifest; commit-specific dev tag and --prerelease --latest=false. It does not yet include explicit semantic version and complete suite/test status in the manifest; its dependency is core only, not every isolated validation suite. Before first publication, extend/review release metadata and dependency/approval scope (at least core, any tests relevant to packaged components; explicitly describe native/actual audio unverified, never conflate a skip with PASS), verify exact release payload and archive listing, and test no-overwrite behavior without publishing. Do not weaken existing approval/permission or LICENSE checks. Repository candidate tree contains no LICENSE; owner-approved license and applicable third-party compliance remain a hard publication blocker. No secret/variable settings changed; approval variable state not inspected. No release created in this continuation. The existing main branch and prior release contents are preserved. See ADR-035 and CI.md.

Rollback: disable SSC_RELEASE_APPROVED without deleting or replacing previous releases. No new workflow or production code in this documentation increment. Existing gate remains in force.
