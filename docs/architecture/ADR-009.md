# ADR-009 — Narrow upstream integration path and lifetime boundaries

Status: PROPOSED, not approved by upstream or runtime-validated. Date: 2026-11-26.

Context: Display Config 1.8.0 supplied source pins its WinMM proxy and installs file detours from DllMain. supreme_hook_proxy/src/config.rs gates resolver initialization on rd_config.txt; hooks/create_file.rs routes reads and writes through it. This is a file-I/O boundary, not a proven game-thread callback. The resolver can be reached from NtCreateFile or NtOpenFile and uses OnceLock; calling a plugin there could re-enter hooked I/O. Source comments describe the intended behavior, not independent proof of lock/thread state on every call. No supported plugin loading contract has been found.

launcher/src/app/ui.rs calls run_injector on Play after saving configs; logic.rs looks for Display_Config_Resources/Injector.exe, calls command.output with that working directory and captures stdout/stderr, with up to two attempts and an exit on success or absent executable. The supplied launcher and game archives do not include Injector.exe or its implementation. This is an optional external-helper path, not proof of safe in-process extension initialization or a contract to repurpose. Do not create or substitute an injector.

Options:
- A: supported maintainer-reviewed native extension boundary with explicit startup, ownership and teardown contract. Preferred.
- B: opt-in external diagnostic that observes only files/manual game behavior. Available now, cannot provide native UI or authoritative timing.
- C: competing proxy, DllMain callback or unknown Injector.exe replacement. Rejected for this increment: loader-lock, ABI, lifetime and compatibility risk.

Proposed sequence for A (not implementation):
1. Existing loader and original game launch unchanged. An agreed extension host loads the optional component only from a controlled game-owned path and establishes an explicit post-loader-lock initialization boundary. Loader choice and provenance must be reviewed before implementation; do not infer safety from a boolean in a host struct.
2. Validate target architecture and actual loaded module identities against reviewed references, then negotiate a narrow C ABI using fixed-width fields, explicit version/size, cdecl where agreed, opaque owned context and no cross-allocator STL or Rust objects. Current mock ABI is not the native contract. Unknown/incomplete builds or incompatible negotiation fail closed with no native capabilities.
3. Installed-disabled mode: no engine hooks, memory reads, menu mutations, network, capture or gameplay changes. Test clean game, Display Config plus original and keyboard-patched builds; exit normally; remove only companion-owned components; compare baseline. Host lifetime/initialization and rollback evidence required for G1.
4. Only after G1, introduce one read-only observation at an identified engine-owner-thread boundary. Menu and result objects remain engine-owned; no borrowed pointer is cached across page/mode transitions, destruction or callbacks. Before G2, verify event sequence/identity, control release, finish and final displayed result; distinguish resets/retries/replays. Do not call Get_Results from companion: it mutates presentation state.
5. Controlled shutdown before owner destruction: stop accepting events, stop producers, drain/cancel owned work off game thread, release owned context. If safe removal is not proven, require process exit and never unload a module while callbacks may target its code. Never alter pinned upstream proxy lifecycle or perform blocking teardown under loader lock.

Licensing: upstream LICENCE is GPL v3. No upstream implementation is copied or linked here; GPL compatibility, notices, source distribution and combined-work obligations require review and owner choice before integration/release. No license selected; SSC_RELEASE_APPROVED remains unchanged.

Acceptance: maintainer-reviewed documented loading/lifetime boundary, actual Windows installed-disabled launch/exit and rollback, no destructive replacement, and matching baseline. Until then G1 BLOCKED. Static byte-window matches and CI are not runtime evidence.
