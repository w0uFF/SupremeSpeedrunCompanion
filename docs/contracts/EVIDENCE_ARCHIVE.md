# Experimental evidence archive — schema 1

Scope: independent development tool tools/evidence_archive.py, not the final submission schema or a moderator verdict. Python standard library plus existing evidence_inventory and baseline_snapshot helpers. Use trusted closed staging and an owner-controlled output directory outside staging. Public functions create(root, selected, output) and verify(path). No game thread, game file changes, network or credentials. Create inventories explicit files, writes a new exclusive ZIP, rehashes while copying, and calls the independent reader on the resulting file. No overwrite; detected failures remove the newly created partial output. A process crash can leave a partial file; no crash-safe atomic publish or fsync guarantee. Never use a partial archive as evidence. Original files retained.

Schema: manifest.json is UTF-8 JSON object with schema=1, scope=experimental_evidence_archive and files entries path/role/size/sha256. Flat stored ZIP members only; classic single-disk EOCD, no archive comment or ZIP64 central directory. ZIP64 local headers permitted. 1 GiB total payload, maximum 64 payload files, 64 KiB manifest and 128 KiB central directory; physical archive length checked. No extraction. Reader checks count and central directory bounds before opening ZIP, unique names case-insensitively, safe portable file names, regular member types, no encryption or compression, declared sizes, duplicate JSON keys, exact member set, CRC through zipfile and streaming SHA-256. Successful report states integrity_matches_manifest=true, eligibility_verified=false, complete_submission=false. Matching a self-contained manifest is not authenticity or proof of unmodified gameplay. No identity, timing provenance, full package manifest, playback, signatures, safe extraction or imported run registration yet. Do not treat as a hardened sandbox for adversarial input; local path/parent races, hardlinks and parser resource/security testing remain open. No compressed import, large recordings over 1 GiB or legacy format supported. These limits are reversible development choices, not competition requirements.

Tests: tests/test_evidence_archive.py (six cases: roundtrip, exclusive destination, mutation mismatch, traversal/collision/extra member, duplicate manifest key, bound/cleanup and compression). CTest P0_evidence_archive. No game files involved. Future G4 requires immutable manifest provenance, crash recovery, larger file policy and independent validator integration.
