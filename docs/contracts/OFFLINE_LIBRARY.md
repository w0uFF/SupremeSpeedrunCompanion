# Offline SQLite reference implementation — schema 1

Scope: tools/offline_library.py, independent from the C++ bootstrap. Python 3.10+ and standard-library sqlite3. No new shipped runtime dependency. Prototype actual persistence, not a production database migration or completed run manager. Caller supplies a trusted, explicit database path outside the game. Owner-thread usage; no async UI or thread synchronization. Close explicitly; transactions commit or roll back. New empty DB initialized under a write transaction, PRAGMA user_version=1. Nonempty unversioned or unsupported version rejected; table/column presence probed. Not a comprehensive validator for arbitrary imported SQLite files; do not open untrusted DBs.

Preferences: remember boolean, paired rider/board IDs or both null, recording policy automatic/ask/training. Saved IDs are not validated native loadouts; existing Availability port must recheck before applying. No API credentials, game save writes or implicit default fallback. Missing row returns None.

Run: caller-generated stable 32 lowercase hex ID, category label/ID supplied by caller, SHA-256 of exact comparison profile (not approval), event semantics key, origin local/imported, status finished/abandoned/restarted/failed, nullable IGT integer ms and RTA integer ns in signed SQLite 64-bit range. Unfinished runs may not have final IGT. IDs/category membership, rule validity, capture integrity and official times must be checked externally. Zero is distinct from unknown. Insert-only through API; duplicate ID fails; this is not tamper-proof storage. Separate label table stores display name and favorite without modifying run metadata. History ordered by insertion (max 1000 per call), not race date. Best_local uses exact category/profile/semantics and explicit IGT or RTA query, local finished runs with non-null time only; deterministic run ID tie-break. No imported PBs, no official leaderboard or eligibility claim.

No deletion, imports, date/time metadata, manifest references, recovery testing under power loss, native UI or C++ binding yet. This provisional schema must not be used as final evidence format; migration, pagination, immutable manifest linkage and storage-port design required before integration. Tests cover close/reopen, immutable duplicate rejection, metadata separation, comparison isolation, missing/invalid values and unsupported schema. Remove tool/test without modifying native components.
