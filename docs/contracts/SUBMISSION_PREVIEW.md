# Speedrun.com v1 — request preview and future service boundary

Reviewed 2026-11-26: official API docs https://github.com/speedruncomorg/api/blob/master/version1/runs.md and https://github.com/speedruncomorg/api/blob/master/authentication.md. The documented submission endpoint is POST /api/v1/runs, nested run object, category identifier, level for individual-level runs, numeric seconds in times, video URL, optional platform/region/date and required variables depending on game. Ordinary account submissions must not override players or set moderator verification. API-key authentication uses X-API-Key; the published key acquisition workflow is manual copy/paste, not OAuth. Documentation is not live game metadata, transport validation or moderation approval.

tools/submission_preview.py preview(category,platform,video,run_date,igt_ms,level=None): pure, deterministic, no network or credentials. Uses explicit caller-supplied eight-character IDs, canonical ISO date, preliminary HTTPS video URL without credentials, local integer 0..604800000 ms bound and numeric ingame seconds. Bound and URL restrictions are local prototype choices, not rules. Assumes native non-emulated preview, omits unsupported variables/region, RTA and player override; never assumes the requested category or level mapping is correct. Returns path/method/body_json plus metadata_verified=false and dispatch_allowed=false. No supported live transport, no auth, no submission approval, no implication the payload will be accepted. Golden synthetic IDs/invalid-domain videos only; Decimal roundtrip tests check milliseconds. Existing C++ Draft review remains separate; no bypass of its review gate.

Future: resolve live category/level/platform/mandatory variables and permitted methods, confirm rules with moderators, use Windows credential storage through injected port (never SQLite/logs), explicit review and per-run publish authorization; bounded HTTPS worker queue; do not blindly retry ambiguous POST results (duplicate risk), reconcile against account history, handle revoked keys, rate limits and outages. Browser fallback. No automatic uploads or live calls tested.
