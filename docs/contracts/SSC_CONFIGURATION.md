# SSC configuration and player profiles — schema 1

P0-T21 offline prototype, Python 3.10+ standard library. This is the reference settings contract and testable local tool, NOT a native configuration implementation. Module tools/ssc_profiles.py owns typed settings, profile edits, launcher projection and a private JSON store; tools/ssc_profile_cli.py is the command-line controller. No dependencies on game, renderer, recorder, online services or upstream implementation. No reads of live processes or writes to launcher state. No bootstrapping of features. No credentials.

## Launcher boundary
The authored manifest integrations/launcher/ssc/mod.json follows the observed PR66 ModConfig schema. A user may eventually enable mod directory ssc and separately set load_diagnostic=true; default false. It declares SSCNative.dll and SSCInitialize, rules empty (no redirects or patches), 21 controls including 18 settings. The prototype never creates or changes mods.json, never interprets other mods' parameters, and never sets the enable flag. No raw user text interpolation into INI; offline resolve reads a caller-supplied copy of active.configuration.ssc as structured JSON. This deliberately avoids patching source INI, path interpolation, and conflicts with staged INI lifetimes. Actual launcher parsing/rendering and native consumption NOT_RUN. Source inspection, not a tested upstream round-trip. The existing upstream full-mod presets are separate; no dynamic SSC profile dropdown or dedicated GUI exists in the supplied revision.

## Ownership and precedence
Profile store: separate SSC-owned private JSON path; schema 1, active exact profile name, 1..64 profiles. First-use Training is selected, with auto record/audio/package disabled, overlay optional, hotkeys unassigned. Other starter profiles Speedrun Tryhard, All Tracks and Low Performance are editable. All Tracks currently copies Tryhard preferences; it does not activate sequencing, which remains a separate race-mode selection. Settings names/values and constraints are generated from FIELDS. Numeric launcher slider values must be finite integral values in range; types, unknown fields and duplicate JSON keys fail closed. Resolution, fps, bitrate, encoder are provisional requests, not validated hardware capabilities. Empty package_directory means application-owned future default; nonempty only absolute local-drive nonroot lexical path; Unicode supported; no existence, permission, free space, reparse or junction guarantee. Validate actual filesystem in future adapter. Duplicate assigned hotkeys rejected; no actual binding. Retention values are preferences, no automatic deletion. Player profiles are distinct from competition profiles and cannot grant eligibility.

Offline session projection: validate profile store and launcher SSC configuration. Blank profile_name selects stored active; explicit name must exist. use_launcher_overrides=false uses selected profile. True uses the entire launcher settings group (manifest defaults plus supplied values), not per-field fallback to profile. A diagnostic is requested only if ssc is present in active.order AND active.enabled AND load_diagnostic is true; report still has native_capabilities=false. Projected snapshot has schema, profile, effective settings, source, diagnostic_requested and local SHA-256. Never publish raw path or snapshot hash as proof of eligibility; no actual run manifest binding. Future in-game edits change local profile or session settings explicitly, take effect only at safe boundaries; active-run snapshot immutable. Launcher override selection reapplies on next game start until disabled. No automatic writeback to launcher or other mods. GUI and native adapter not implemented. No concurrency protocol yet; prohibit parallel writers.

## Persistence and CLI
Explicit path in an existing owner-controlled private directory. Max 256 KiB read/write, duplicate keys and unknown versions rejected. Exclusive initial publication by same-directory hard link, updates via fsync temp + os.replace after validating existing state. Existing malformed/unknown-version/absent store is never silently replaced. No directory fsync, crash/power loss guarantee, hostile-path or concurrent writer defense. Hardlink support required for creation. Keep backups; future migration must be explicit, tested and preserve original bytes. No older schema exists yet. Profile names bounded ASCII, case-insensitive collision rejection. Active cannot be deleted. No actual game data is deleted.

Examples, run outside game in a private scratch directory:
```powershell
python tools/ssc_profile_cli.py C:\scratch\ssc\profiles.json init
python tools/ssc_profile_cli.py C:\scratch\ssc\profiles.json show
python tools/ssc_profile_cli.py C:\scratch\ssc\profiles.json duplicate Training --target "Evening Practice"
python tools/ssc_profile_cli.py C:\scratch\ssc\profiles.json select "Evening Practice"
python tools/ssc_profile_cli.py C:\scratch\ssc\profiles.json resolve --mods-state C:\scratch\ssc\mods-copy.json
```
Create/replace accept --values with a complete settings object; rename/duplicate take --target. No graphical profile manager yet. Unit entry python tests/test_ssc_profiles.py -v. Native C++ configuration/bridge, actual launcher UI fixture, profile import/export user interface, per-attempt immutable snapshots and migration tests remain next work. All settings inactive until relevant gates pass.

T21 follow-up: native typed configuration port in src/modules/configuration/public/settings.hpp (see module README). Injected Store and PathPolicy, exact whole-group precedence, isolated session edits and explicit persistent replace; snapshots copied by value to protect a caller-owned attempt copy from later edits. Strict local GCC/UBSan fake-store tests passed. No native parser, persistence, path policy or launcher adapter; cross-language conformance and actual UI remain pending.

## T22 native file contract and development editor
Native codec accepts the bounded canonical schema-1 subset (ASCII JSON with escaped Unicode UTF-16, object/string/boolean/unsigned integer, 18 exact settings, schema and count checks); not arbitrary JSON, raw UTF-8 text, UTF-8 BOM or a native mods.json parser. Stable textual enum values, deterministic sorted output. Python store emits the same subset; cross-language canonical test includes supplementary Unicode. Python path check now uses UTF-16 units and rejects surrogate/reserved device names to match native lexical policy. The actual store is separate from launcher state. Win32 FileStore reads a fixed profiles.json in an existing private fixed-drive directory, rejects reparse points along the checked directory, profile reparse/hardlinked files, oversized files and invalid data. Same-directory exclusive temp creation, FlushFileBuffers, MoveFileExW with write-through; initial creation refuses replacement, normal update first validates existing data. Single writer, trusted directory, no guarantee against concurrent changes, TOCTOU, disk/power failure or hostile filesystem. No automatic migration. Python/native interchange verified for canonical files; all writes should use canonical encoding. Native directory resolution does not create directories and checks free space only when explicitly called; no reservation, ACL/write check, or recording activation. Empty path needs caller-provided application default. Actual game use pending.

Offline SSC GUI: initialize an existing private store with the CLI, then run `python tools/ssc_profile_gui.py C:\scratch\ssc\profiles.json`. Tkinter required. Local virtual-display smoke creates all 18 controls, saves, duplicates, activates; no human UX validation, actual launcher/in-game integration, import/export or full interaction test. CLI and native writer must not run concurrently with GUI. See docs/product/LAUNCHER_PROFILE_PROPOSAL.md.

## T23 native read-only projection and profile exchange
Native launcher_json.hpp supports bounded PR66 JSON including actual UTF-8, optional BOM, escapes, arrays/objects, bool, null and numeric lexemes; 256 KiB, depth 12, 16384 nodes, 1024 elements per container, 4096 UTF-16 string units and 128 number characters. Duplicate keys and malformed input rejected even in unrelated fields. Only active SSC fields interpreted; active object required, exact SSC names, no manifest execution or rules interpretation. Settings defaults from typed contract, exact decimal integer slider conversion (bounded exponent ±256), explicit complete-group override, order AND enabled gating. Representative Python/C++ conformance, not equivalence over all JSON (Python floating point may round edge-case decimals). Unknown SSC settings fail closed. Standalone Win32 preview reads fixed mods.json and profiles.json from explicit existing private copied directories, no creation, no writes, no path discovery; shared plain-file read rejects reparse, hardlink and oversized files. Trusted directory/single-writer assumptions unchanged. Output includes local path, not submission evidence. Actual upstream save_mods_state interoperability verified in final PR66 fixture. No in-DLL consumption.
AttemptSettings owns const Snapshot by value, validates on construction and exposes const reference. No link to live profile, run ID, evidence hash or actual race yet.
CLI export <name> --file and import --file --target (see --help for full invocation); GUI import/export with same functions. Single-profile schema-1 book, package_directory always blank on both import/export, no overwrite export, case-insensitive name collisions refused, active profile unchanged. No automatic migration or code execution. Python save expected-book check detects stale state before write, not atomic compare-and-swap, TOCTOU/concurrent-write protection or crash guarantee. Keep single writer. Local simulated dialog smoke and Windows automated tests passed; actual launcher/in-game UI not run.
