# C++ player preferences port — source-level prototype

src/modules/player_setup/application/preferences.hpp: Preferences holds remember, optional paired Loadout and existing RecordingPolicy. PreferencesStore exposes load (optional; absence is distinct from exception) and save. Controller borrows store and Availability, both must outlive controller, synchronous owner-thread use. remembered delegates to existing resolve so stale/unavailable saved loadout never auto-selects. update rejects empty or unavailable loadout and invalid policy before saving. No implicit persistence on resolve, native commands, credentials or runtime feature registration. Adapter must implement durable storage and error handling; caller must handle failures and schedule storage off gameplay thread before native integration. Test-only in-memory adapter exercises revalidation, disabled remember, missing data and explicit read/write failure. Existing Python SQLite reference store is unchanged and not wired to C++. Production run-store port, backend/migrations and complete module integration remain open. No binary ABI or on-disk contract changed.
