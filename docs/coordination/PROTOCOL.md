# SSC parallel development protocol (A/B)
Owner-authorized two-agent development; English repository deliverables. Additive to 01_PROJECT_SPECIFICATION.md and 02_DEVELOPMENT_PROTOCOL.md, not a replacement. Both agents must read the governing documents, current PROJECT_STATUS and relevant contracts before development. Start from verified main, record exact SHA, inspect current remote refs each turn. No autonomous agent-to-agent messaging or background execution is assumed: each separately invoked chat reads/writes GitHub Markdown and may use PR comments. User triggers each turn.

## Ownership
| Scope | Owner |
|---|---|
| Native engine bridge, reverse engineering, engine docs, loader/launcher integration, race lifecycle, timing and input, native readiness | GPT A |
| Release readiness and packaging (release workflow portions, docs/release, release-specific tests/scripts); offline submission/export/run management and standalone moderator validation after release-readiness milestone | GPT B |
| Main, active validation PRs, integration queue, root CMakeLists, version numbers, shared contracts, canonical PROJECT_STATUS/CHANGELOG/ROADMAP/README/TEST_MATRIX/KNOWN_ISSUES, CI test jobs and capture implementation | GPT A as integration coordinator |
| Release publishing, license choice, risky native action, rules | Project owner (moderators decide rules) |

Ownership is exclusive by default. B may edit only its feature-specific paths, including docs/contracts for B-owned features only where not a shared contract; changes to common contracts, root build registration, canonical docs, version, other modules or shared CI test jobs must be proposed in B's journal with exact patch/rationale, not committed to those files. A owns integration but must not modify B feature files without an explicit handoff recorded by B. If a task overlaps, stop that portion, record REQUEST with exact files/contract, continue independent work. A owns T45 PR20; B must never write it. A may only promote after applicable gates pass. Neither agent claims approval by the other without an actual remote review.

## Branches and communication
- A writes only gpt-a and authorized integration/validation branches. B writes only gpt-b. No force-push, rewriting history, branch deletion or automatic merge from the other branch. Before write, fetch current head; use expected SHA lease and fast-forward only. Avoid multiple concurrent turns on the same agent branch.
- Both read remote gpt-a:docs/coordination/GPT_A.md and gpt-b:docs/coordination/GPT_B.md at the start of every turn, not the stale copies inherited on their own branch. Record observed peer head and message IDs. Each owns only its journal; no shared writable inbox. Shared protocol changes only by A after recorded coordination. Git history preserves messages.
- Append short chronological entries with unique ID (A-0001, B-0001 etc.), UTC timestamp if known, exact baseline/head or candidate SHA, task status, file ownership, evidence/test results, dependencies, next action, and addressed message type (INFO/REQUEST/READY/ACK/BLOCKED). Never invent results or ACKs. For candidate delivery record exact implementation commit and list of changed files, tests, known limitations, proposed integration patch and rollback. Respond to peer messages by referencing IDs in your own journal. The owner can copy prompts between conversations when necessary.
- A verifies peer READY against exact tree, tests and ownership, then integrates reviewed changes into a dedicated validation branch from current verified main. B keeps its own working branch; sync forward by explicit merge from verified main only at a safe checkpoint, with no force/reset. Do not import unvalidated T45 code or claim a new baseline until A promotes it. If synchronization conflicts, stop and request A coordination. A never merges B blindly. Do not trigger duplicate expensive capture jobs solely for agent-journal edits. Existing CI remains unchanged by this protocol.
- No GitHub Actions artifact upload/download/storage. Runner-local files only; GitHub Releases for authorized distribution, with immutable version/commit/checksums/manifest and explicit status. No actual publication until approved license/compliance and applicable release gates. Development pre-releases may precede full native validation but remain non-installable while G1 blocked. No hooks, installations, proxy replacement, game execution, production provenance or eligibility/rule changes without applicable authorization/evidence. Keep original archives private and unchanged; no private data or credentials in journals.
- Each agent completes one coherent increment, updates its own journal even when blocked, reports precise validation state, and gives its user a Continue button/copy prompt. No background work claims. A consolidates canonical docs when integrating. B can continue independent offline work while T45 CI runs, but must not bypass the pending T45 promotion gate.
